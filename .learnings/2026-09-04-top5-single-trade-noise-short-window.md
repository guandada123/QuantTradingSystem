- **状态**: 已修复并验证（`low_sample` 五天来首次翻转 false）
- **✅已升级(2026-09-06)**: 是

## 现象

08-31 ~ 09-04 连续 5 天的日报，Top5 无一例外：

```
total_trades = 1     win_rate = 100.0%     sharpe = 14 ~ 61
flags: low_sample=true, min_trades_applied=true
```

此前 5 天的记录里每天都写「单笔假象，不可引用」，但**一直没找到根因**。
09-02 还写过一条 `LRN-20260902-001（★）`建议「Top5 排序改 overfit_ratio + wf_stability
优先于 sharpe」—— 方向错了，**重排救不了没有合格候选的池子**。

## 根因（两个独立缺陷叠加）

### ① 回测窗口只有 90 天，短到统计上不可能得出结论

```python
def _default_start_date(self, report_type, end_date):
    if report_type == "daily":
        return (end - timedelta(days=90)).isoformat()   # ≈ 61 个交易日
```

慢策略（ma-cross 5/20、macd 12/26/9、kdj）在 3 个月里只产生 0~2 个信号。
实测（150 只 × 11 策略 = 1650 次回测）：

| 窗口 | ≥3 笔 | ≥5 笔 | ≥8 笔 |
|------|-------|-------|-------|
| 90 天（原值） | 1.5% | **0.0%** | 0.0% |
| 365 天 | 38.3% | 9.9% | 0.4% |
| **730 天（现值）** | 58.1% | **27.0%** | 5.3% |

**90 天时全池没有一次回测能达到 5 笔** → `min_trades >= 5` 的过滤**必然落空**
→ 保底退回单笔结果。不是排序问题，是**根本没有够格的候选可排**。

### ② 即使有够格候选，挑选也只在排名前 10 里做

```python
top_strategies = sorted(_rankable, key=_rank_score, reverse=True)[:10]   # ← 先截 10
# generate_daily_brief 再从这 10 条里筛 min_trades
```

够格的候选排在第 11 名开外就**永远进不来**。
改完 ① 之后 Top5 只出 2 条（且 trades=4 < 5），就是这个缺陷在作祟。

## 修复

1. `WINDOW_DAYS = {"daily": 730, "weekly": 730, "monthly": 1095}`（原 90/180/365），
   用类常量暴露，便于调参。报告仍是滚动窗口、report_date 仍是当天，不是把日报改成年报。
2. `MIN_TRADES_TIERS = (5, 3, 1)`：在**全量**候选里先挑 ≥5 笔的，不足 5 条则放宽到 ≥3，
   仍不足才退回原始排名并靠 `low_sample` 标记如实暴露。
   宁可返回短名单，也不用噪声补齐到 5 条。
3. 更新 3 条断言旧窗口的测试，新增 4 条守卫测试
   （`TestMinTradesTierSelection` / `test_windows_are_long_enough_for_min_trades`）。

代价：150 只 2.2s → 3.0s；全量回测 13s → **26s**，可接受。

## 修复效果

| | 修复前（90 天） | 修复后（730 天 + 全量挑选） |
|---|---|---|
| Top5 交易笔数 | 1 / 1 / 1 / 1 / 1 | **5 / 8 / 5 / 6 / 5** |
| Top5 胜率 | 100% ×5 | **60% / 37.5% / 60% / 50% / 60%** |
| 最佳夏普 | 46.0（纯噪声） | **4.67** |
| `low_sample` | true（连续 5 天） | **false** ✅ |
| `wf_passed` | 2/30 | **4/30** |
| 平均收益（窗口） | 2.05%（3 个月） | 12.55%（2 年） |

`low_sample` 翻转 false 是修复生效的判据 —— 这个值之前 5 天天天是 true。

## 教训

1. **"指标异常"先看样本量，别急着改排序算法。**
   连续 5 天的记录都把现象记成了"排序/标注问题"（09-02 甚至建议改排序权重），
   但真相是**池子里没有合格候选** —— 排序再好也排不出不存在的东西。
   判据很简单：先量一遍 `total_trades` 的分布，比盯着 sharpe 看有用得多。
2. **任何"最少样本量"的过滤，都必须先确认样本里真有够格的对象。**
   过滤条件静默落空是最危险的一种失败：代码在跑、结果在出、没有报错，
   只有结果全是噪声。写过滤时配一条「有多少比例通过」的日志或断言。
3. **截断后再过滤 = 过滤形同虚设。** `sorted(...)[:10]` 然后在这 10 条里筛 min_trades，
   等于把过滤的搜索空间砍掉了 99.9%。**顺序应该是：先过滤，再排序，最后截断。**
4. **短名单优于噪声补齐。** 凑不满 5 条就返回 2 条并如实标记，
   比填 3 条 1 笔的假数据体面得多 —— 下游至少知道数据不够。
