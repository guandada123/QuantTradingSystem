# 间接统计探针的系统性误报：不要用 vol/MA(均值) 判"快照污染"

- 日期：2026-09-04
- 场景：Quant 数据管线（automation-1781663740184）PHASE 3 数据校验
- 等级：✅已升级(2026-09-06)（可推广到一切"用统计量反推数据是否被污染"的探针）

## 事情经过

承接 09-03 定案（`2026-09-03-intraday-snapshot-frozen-as-daily-bar.md`）：
盘中快照被固化成日 K，成交量系统性偏小。已用 `--refresh` 修复。

本轮想加一道"快照残留"扫描。我没有直接用权威源对拍，而是先设计了一个**间接**探针：

```sql
-- 对每个历史日期，算 当日vol / 该股21日均量 的横截面中位数，<0.85 判为疑似快照
AVG(vol) OVER (PARTITION BY ts_code ORDER BY dt ROWS BETWEEN 10 PRECEDING AND 10 FOLLOWING) AS ma21
```

结果：90 天窗口里**命中 14 个日期**（07-07 / 07-08 / 07-23 / 07-24 / 07-27 / 07-28 / 08-03 /
08-12 / 08-20 / 08-21 / 08-25 / 08-26 / 09-02 / 09-03），看起来像"修复不彻底，还有残留"。

**但逐个与腾讯源对拍后，这 14 个日期全部为 0 偏差。全是误报。**

## 根因

成交量是**右偏分布**（偶尔放巨量，多数日子偏小），所以：

- `median(vol) / mean(vol)` **天然就落在 0.75~0.85**，这不是污染特征，是分布形状。
- 我拿"中位数 ÷ 均值"当比值，等于把分布偏度当成了信号，阈值 0.85 正好卡在
  自然分布区间内 → 必然误报约 1/3 的日期。

对照 09-03 那次为什么能测出来：当时污染极其严重（成交量偏差中位 62.8%，
即 DB 只有真实量的 37%），**信号强度远远盖过分布偏度**。一旦数据被修好、
只剩正常波动，同一个探针就退化成纯噪音。

## 教训

1. **间接统计探针必须先标定，不能拍阈值。** 拿"看起来合理"的常数（0.85）去切一个
   本身有偏的统计量，等于制造误报机器。正确做法：先在**已知干净的基线**上跑一遍，
   看该统计量的自然分布区间，再把阈值设在区间外。
2. **中位数和均值不要混用做比值。** 分子用 median、分母用 mean，比值天然 <1，
   这个 1 不是"正常水平"。要同口径：median/median 或 mean/mean。
3. **能直接对拍就别间接推断。** 与权威源逐行比对（DB vs 源）是**零误报**的：
   同一数据源要么等要么不等，没有"分布形状"这层中间解释。本例中直接对拍
   20 行，输出 `成交量偏差 中位=0.0000% 最大=0.0000%`，结论干净明确。
   间接探针的价值只在于"对拍太贵时做粗筛"，且命中后**必须回落到对拍确认**。
4. **误报的代价是信任**。一次误报 14 个日期，如果据此推 🔴 卡片，用户会去查
   不存在的故障；更糟的是第二次真出问题时，告警已经被当噪音忽略（狼来了）。
