# 定级数据问题前先查下游消费方：不然会修错地方、加错调度

- 日期：2026-09-04
- 场景：Quant 数据管线（automation-1781663740184）"是否要加 15:30 盘后重跑"决策
- 等级：✅已升级(2026-09-06)（可推广到一切"数据脏了 → 抢修/加冗余"的决策）

## 背景

09-03 定性了一起严重事故：`daily_kline` 被盘中未收盘快照污染
（29 个交易日 / 1480 行，成交量偏差中位 62.8%）。已用 `--refresh` 修复。
当时留了一个待决策项：

> ① 建议增开 15:30 盘后重跑（带 `--refresh`）或本管线整体改盘后，
>    否则当日 K 仍会被盘中固化。

本轮要拍这个板。按直觉，数据脏了就应该在"数据正确的时间点"再跑一次 —— 加个 15:30。

## 先查了消费方，结论反转

没有直接加调度，而是先回答一个问题：**这张表到底被谁用？**

```bash
grep -rn "FROM daily_kline" --include=*.py .
```

结果（全仓 + Claw + StockInsight 跨项目扫描）：

| 消费方 | 用法 | 是否受影响 |
|---|---|---|
| `strategy-service/services/report_service.py` | 从 `daily_kline` **取股票代码清单**作为回测 universe 的**兜底**分支 | 仅代码清单，不取价格 |
| 其余 `daily_kline` 命中 | 全是 **provider 方法名** `get_daily_kline()`，不是读表 | 否 |
| Claw / StockInsight | 0 引用 | 否 |

关键结构（`report_service.py`）：

```
1) 主路径：daily_quote 取流动性>=3亿的标的  ── 全市场 3200 只，16:30 盘后回填
2) 降级：daily_quote 老查询
3) 回退：daily_kline（小样本池，仅取 ts_code，HAVING COUNT(*) >= 20）
```

**回测用到的价格数据根本不来自 `daily_kline`**，而是走
`data_service.py → provider(tushare/akshare/wind/tdx).get_daily_kline()` 实时取。
`daily_kline` 表只在这条链全挂时，提供一个"有哪些股票可回测"的清单。

## 决策：不加 15:30 重跑

| 方案 | 判断 |
|---|---|
| 加 15:30 盘后重跑 | ❌ 否决 |
| 整体改盘后 | ❌ 否决 |

理由：

1. **影响面不支持**。污染的是一张只用于"兜底代码清单"的表。清单少一天、多一天，
   对 `HAVING COUNT(*) >= 20` 的成员判定没有任何影响。
2. **加调度会制造新风险**。15:00–16:30 已经是全天最挤的窗口：
   15:00 知识库信号溯源 / 15:07 盘后账户汇总 / 15:10 portfolio 同步 /
   15:30 StockInsight 收盘扫描 / 15:40 选股扫描 / 15:50 综合复盘+晚报 /
   16:30 全市场回填 + 自动补跑。
   而平台 `concurrency=3` **不执行限流**（09-02 定案），排队才是主要故障模式。
   为一个兜底路径往最挤的窗口再塞一条，是净负收益。
3. **已有自愈机制**。`--refresh` + `--days 90` 意味着下一轮自动覆盖上一日的快照，
   污染窗口恒定为 1 个交易日，且该表不服务实时/准实时场景。

## 教训

1. **给数据问题定级前，先跑一遍 `FROM <table>` 的引用扫描，确认下游是谁、怎么用。**
   "表脏了"和"表脏了且有人靠它决策"是两个完全不同的严重度。
   本例中如果不查，就会往最挤的时段加一条几乎无收益的调度。
2. **`grep` 命中不等于真的在读表**。本轮 `daily_kline` 在 15 个文件里出现，
   但绝大多数是 **provider 方法名** `get_daily_kline()`。
   要搜 `FROM daily_kline` / `JOIN daily_kline`，而不是搜表名本身。
   （呼应 08-30 铁律：危害面核验须 grep 符号不是文件名 —— 这次是同构的陷阱，
   只不过假阳性来自"方法名"，不是"文档里的文件名"。）
3. **"修数据"的解法不只有"在数据正确的时间再跑一次"**。
   还有"确认没人真的需要它此刻正确"，后者成本为零。
   先穷举下游，再选解法。
4. **决策要写回 prompt**，否则下一轮执行者会重新打开同一个问题。
   已在 automation prompt 内写明"已评估，不加盘后重跑"及理由。
