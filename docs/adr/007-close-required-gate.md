# ADR 007：行情 close 必填闸 —— 先观测、后强制

- 状态：Proposed（第一阶段「观测态」已实现，见文末）
- 日期：2026-11-27
- 背景来源：`disc-20261027-02`（行情价格合理性校验）落地后的独立复核

## 1. 问题

`services/price_sanity.py` 的 `bar_problems()` **有意**放行缺字段的 bar：

```python
if v is None:
    continue  # 缺字段不算坏数据（不同数据源字段不全）
```

这个取舍本身成立（「缺字段」与「价格不可能存在」是两类问题）。但**消费侧**没有第二道闸：
`data_service._screen_quotes()` 只调 `screen_bars()`，于是 `close` 缺失的 bar 会原样进入
收益计算与回测。停牌股在部分数据源里写作 `"--"`，`float("--")` 抛错 → `_f()` 返回 `None`
→ 被当作「没字段」放行。

风险形态：**不报错、静默参与计算**，属于本仓反复治理的「假数据静默流入」一类。

## 2. 实测分母（不是推测）

查生产库 `daily_quote`（PG，只读）：

| 指标 | 值 |
|---|---|
| 总行数 | **3,315,977** |
| `close IS NULL` | **0** |
| `close <= 0` | **0** |
| 标的数 | 5,045 |
| 覆盖区间 | 2023-01-03 → 2026-11-26 |

**结论：强制闸对现有全部历史 = 一条不剔（Δ=0）。**
即「加闸会不会改变历史回测结果」这个问题，在**已落库数据**上是可证否的：
不会。它唯一的价值是防**未来**的取数回归（某天数据源开始返回 `"--"`）。

推论：昨晚担心的「加闸会改变进入回测的 bar 集合、且事后无从归因」，
在数据层面不成立；剩余不确定性只在「取数即刻、尚未落库」的那一段。

## 3. 设计：两阶段，先观测后强制

### 阶段 A（本次实现）：观测态，只记不打

在 `data_service._screen_quotes()` 里，对**留下来的** bar 统计 `close` 是否为有效正数：
- 若存在缺失 → `logger.warning("close 缺失但被放行", ts_code=…, count=…, sample=…)`
- **不丢弃任何 bar**，行为与现状完全一致

目的：在不改变任何产出的前提下，收集「真实发生率」。若一周内为 0，说明该缺陷只有理论风险；
若 > 0，则拿到具体标的与日期，可作为阶段 B 的样本。

### 阶段 B（待阶段 A 数据后决定）：强制态

依据阶段 A 结果二选一：

| 阶段 A 观测 | 处置 |
|---|---|
| 发生率为 0（预期） | 保持观测态即可；或转为丢弃（成本为零，因为本来就没有） |
| 发生率 > 0 且样本可解释（停牌/源缺字段） | 转为丢弃 + warning，并在 `impact_note` 记录被剔标的清单 |
| 发生率 > 0 但样本是**真实交易数据** | **不改**，改为在收益计算处显式处理缺失（另一 ADR） |

## 4. 验收判据

- 阶段 A：`tests/test_data_service_close_guard.py` 含
  `test_missing_close_is_logged_not_dropped`：注入 `close=None` 与 `close="--"` 的 bar，
  断言 **bar 数不变**（仍返回全部）且 **warning 被调用**（用 caplog 捕获）。
  另含 `test_clean_bars_no_warning`：干净样本不得产生该告警（防「恒告警」式假信号）。
- 阶段 A 的**证伪方式**：把观测代码改成 `pass` → 上述用例必须翻红。
- 阶段 B 的验收（未做）：`select count(*) from daily_quote where close is null` 在
  上线后 7 天仍为 0，且回测指标与 A 阶段基线逐项一致（年化/夏普/最大回撤/交易笔数）。

## 5. 回滚

观测态是**纯日志**，删除该分支即回退，无数据影响、无配置开关。

## 6. 被否决的方案

| 方案 | 否决理由 |
|---|---|
| 直接在 `bar_problems()` 里把缺字段判为硬错误 | 会改变 `price_sanity` 的公开契约（「只判不可能存在的数据」），且不同数据源字段不全时会误杀整条 bar，波及范围远超 close |
| 直接上强制丢弃（跳过观测态） | 实测 Δ=0 使强制看似安全，但「取数即刻」那一段没有数据支撑；先观测一周的成本近乎为零，收益是拿到真实样本，不值得省 |
| 在回测引擎里过滤 | 太靠下游：此时 bar 已参与中间计算，过滤点越晚，越难说清影响面 |
